# Reporting a problem

There are two very different kinds of "this is wrong": a subtitle that's
just bad, and one that shouldn't be here at all.

## A subtitle is bad

Down-voting it is the everyday tool — see
[Votes and stash-box](web/votes-and-stashbox.md). A down-vote always
needs a reason (out of sync, wrong content, wrong language, low quality,
or spam), which is itself a kind of flag: enough net downvotes, or even
a single **spam** vote, puts the track in front of a moderator without
you doing anything else.

## Requesting removal

For anything stronger — a copyright claim, content depicting someone
without consent, or anything else that needs to actually come down —
every release page has a **Report this subtitle / request removal**
section under each track. It needs no account:

- **Reason**: copyright, depicts me, illegal content, wrong or harmful,
  or other.
- **Details**: required if you picked "other".
- **Contact**: optional — leave it if you want a reply.

This goes straight to the moderation queue, not a public comment: nobody
browsing the release page can see that a request was filed, or how many.

If you want a paper trail, or the removal form doesn't fit your case,
email the node's operator instead — a node that publishes an address
shows it on its **Contact** page.

## What "withdrawn" means

A valid request gets the track (or, if the whole release needs to go, the
whole release) **withdrawn**. A withdrawn track stops appearing anywhere
— search, browse, the plugin's lookups, downloads — immediately.

Withdrawal is a soft delete, not a hard one: the record itself stays, so
the removal can be explained later and reversed if a request turns out
to be mistaken. That also means it isn't instantaneous everywhere —
nothing here is ever hard-deleted, and a dump or a mirror of this node
taken before a withdrawal can still hold a copy until whoever runs that
copy withdraws it too.
